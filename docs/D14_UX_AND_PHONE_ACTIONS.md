## 1. Чат: ответ ИИ больше не теряется

### Поворот экрана во время запроса (было: ответ хоста молча пропадал)

Запрос жил в `lifecycleScope` активити — поворот/смена темы/языка отменяли
корутину. Теперь запросы идут через процессный `agent/ChatRequests`:

- один запрос за раз (`inFlight: StateFlow`), busy-состояние UI выводится из
  него, а не из поля активити;
- ответ получает подключённый `Listener` (текущая `ChatActivity`); если
  активити нет (пересоздаётся или закрыта) — ответ пишется прямо в
  `ChatStore`, следующий экран его увидит;
- Stop (`abort()`) разблокирует UI и отбрасывает запоздавший ответ по
  `seq`; сам запрос на хосте досчитывается (реальная отмена — см. «Дальше»);
- подтверждение инструмента агента (`Reply.Confirm`) паркуется в
  `pendingConfirm` до ответа пользователя — диалог, закрытый поворотом,
  показывается снова, а не подвешивает цель агента. Без связи с хостом
  подтверждение остаётся припаркованным (раньше терялось).

Проверено: поворот сразу после отправки → ответ приходит в тот же чат.

### Прочее в чате

- **Повторить**: у последнего пузыря ошибки (перед ним — сообщение
  пользователя) кнопка `retryAction` — убирает неудачный ход и спрашивает
  заново. Проверено обрывом Wi‑Fi.
- Невыпущенные вложения переживают поворот (id/имя/mime/размер в
  `Bundle`, файлы не удаляются при `isChangingConfigurations`).
- Точки «печатает…» только под чатом, который реально ждёт ответа.
- Toast → Snackbar; «Скопировано» не дублируется на API 33+ (система
  показывает свой оверлей).
- Код-блоки: копирование по `code.hashCode()` — кнопка работала только
  один раз после ребинда.
- Имя вложения берётся из `OpenableColumns.DISPLAY_NAME`.

### Настройки

`activity_main.xml` разбит на секции «Подключение / Личное / Приватность /
Прочее»; у «Возможностей», «Языка» и «Вида уведомлений» свои иконки
(`ic_apps`, `ic_language`, `ic_notif_style`). Точка статуса — `View` 10 dp с
`widget_dot` и `backgroundTintList` вместо текстового «●».

## 2. Capability: ошибки, которые хост не видел

Найдено вызовом каждой capability с хоста через Python SDK.

- **`calls.recent` всегда таймаутил.** `CallLogProvider` со строгой SQL-
  грамматикой бросает `Invalid token LIMIT` на `"date DESC LIMIT n"` в
  sortOrder. Лимит теперь передаётся как `ContentResolver.QUERY_ARG_LIMIT`
  (`caps/LimitedQuery.kt: queryLimited`), а `Cursor.rows(limit)` страхует
  провайдеры, игнорирующие аргумент. Применено в calls/SMS/contacts/calendar.
- **Исключение в Kotlin-провайдере = тишина.** UniFFI превращает его в Rust-
  панику на blocking-потоке, ответ не уходил, хост ждал свой таймаут.
  `caps::handle_action_request` оборачивает `dispatch()` в `catch_unwind` и
  отвечает `ActionError("{cap} provider failed: …")`. Тест
  `throwing_provider_yields_action_error_not_silence`. (В профиле сборки нет
  `panic = "abort"` — если его когда-нибудь добавят, эта защита исчезнет.)
- **`geo`: «no location fix yet» навсегда**, когда геолокация выключена или
  нет разрешения. `LocationProvider::unavailable_reason()` отдаёт причину.
- **Экран «Возможности»**: строки спецдоступа («Изменение системных
  настроек», «Не беспокоить») всегда показывали «вкл» — `all {}` по пустому
  списку runtime-разрешений = `true`, а поиск по индексу съезжал при
  добавлении строк. Теперь у строки своя лямбда `specialGranted`.

## 3. `sms.send` и `calls.dial` с подтверждением на телефоне

Протокол — в [HOST_CAPABILITIES_PROTOCOL.md](HOST_CAPABILITIES_PROTOCOL.md).
Коротко: `{"action":"send","to":"+998…","text":"…"}` и
`{"action":"dial","number":"+998…"}`.

Модель угроз: у хоста (агент, скрипт, любой с токеном устройства) есть только
**запрос**. Ничего не уходит с телефона без тапа пользователя.

- **Rust (`caps/device.rs`)** проверяет до провайдера: номер — цифры с
  необязательным `+`, 3–15 цифр, пробелы/дефисы/скобки выкидываются; USSD
  (`*100#`) и буквы отклоняются. SMS ≤ 1530 символов (10 GSM-7 сегментов).
  Ответ провайдера — `ConfirmedActionResult { Done | Declined | Failed }`;
  `Declined` → ошибка `declined on the device: <причина>`, чтобы агент не
  повторял.
- **`caps/ConfirmGate`**: high-priority уведомление «Разрешить / Отклонить»
  (активити из фона Android не даёт открыть). «Разрешить» требует
  разблокированного телефона (`setAuthenticationRequired`); смахивание =
  отказ; 20 с без ответа = отказ; первый ответ побеждает. Номер — в тексте
  уведомления, не в заголовке (заголовок обрезал его до `+998…`).
- **Бюджет времени**: всё действие (подтверждение + работа) укладывается в
  27 с < 30 с дефолтного таймаута ядра — иначе одобрение, пришедшее после
  таймаута хоста, провоцирует повторную отправку. Ожидание результата
  радио для SMS (до 8 с) урезается до остатка бюджета; «нет вердикта в
  срок» = отправлено (система уже поставила в очередь).
- **Звонок** — `TelecomManager.placeCall`, не `ACTION_CALL`: из фона
  старт активити запрещён. Экстренные номера Android сам не набирает по
  вызову стороннего приложения — открывает звонилку.
- Разрешения `SEND_SMS` / `CALL_PHONE` запрашиваются только с экрана
  «Возможности»; `uses-feature telephony required=false`.

Проверено: отказ, таймаут, «Разрешить» → SMS в «Отправленных»; звонок из
фона → `DIALING`; USSD отклонён в Rust.

## 4. Хост: агент получил доступ к телефону

Вне этого репозитория (конфиг `~/.config/vyn`), записано здесь, чтобы
повторить на другой машине:

1. `agent-tools.json` — 15 инструментов `pixel-6pro.{battery,geo,device,wifi,
   bluetooth,dnd,ringer,brightness,flashlight,launcher,sms,calls,calendar,
   contacts,clipboard}`; для `sms`/`calls` `timeout_ms: 45000` и
   `requires_confirmation: false` (страж — подтверждение на телефоне), в
   описании — «при отказе сообщить пользователю, не повторять».
2. `plugins.d/agent.yaml` — новый токен агента с `pixel-6pro.*` в
   `ipc_targets` и те же имена в `AGENT_PLUGIN_ALLOWED_ACTIONS`.
3. **`systemctl --user restart vyn`**, не `vyn plugin restart agent`: ядро
   читает `plugins.d/*.yaml` только при старте (`state.plugin_defs`),
   `restart` поднимает процесс плагина со старым env. Проверка —
   `/proc/<pid агента>/environ`.

Проверено end-to-end: «What is my phone battery level?» → «24%, на зарядке»;
«Send an SMS to +998… » → уведомление на телефоне → «Разрешить» → SMS в
«Отправленных».

  SMS / звонил) — сейчас след только в уведомлениях.

**Ядро / плагин агента (соседние репозитории)**
- `vyn plugin restart` должен перечитывать drop-in (или нужен
  `vyn plugin reload`): сейчас изменения `plugins.d` молча не применяются.
- Агент звал несуществующие `dev-c5639a.*` / `dev-test-single.*`:
  вероятно, из памяти сессий (`AGENT_PLUGIN_MEMORY`). Агенту стоит
  отбрасывать вызовы вне каталога, а ядру — отвечать на `unknown target`
  ошибкой сразу, а не только `WARN` в лог (агент крутился до лимита шагов).
- Убрать `dev-test-single.*` из `ipc_targets` токена агента, когда тестовое
  устройство больше не нужно.
- Шаблон `agent-tools.json` для телефона держать в репозитории (сейчас
  живёт только в `~/.config/vyn`).
