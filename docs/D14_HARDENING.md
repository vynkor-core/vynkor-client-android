## M1. Безопасность и краши (P0, R-01…R-04)

### Микрофон больше не стримит постоянно (R-01)

Было: сервис агента безусловно стартовал `MicCapture` — телефон непрерывно
лил PCM на хост, пока живо соединение.

Теперь:
- mic→host существует **только внутри явной сессии** (`MicSessionController`,
  владелец — `AgentService`; состояние — `AgentHolder.micStreaming`);
- точка входа в UI — **long-press кнопки микрофона в чате** (обычный тап =
  локальная диктовка через on-device STT, как раньше); UX-жест согласовать
  при желании (роадмап помечал это решением владельца);
- предохранители сессии: idle-timeout 2 мин без единого чанка, жёсткий кап
  5 мин, реакция на «умерший» capture; закрытие чата гасит сессию;
- START_STICKY-рестарт сервиса тоже поднимается **без** микрофона.

### Паринг из внешнего intent — только через подтверждение (R-02)

QR по-прежнему применяется сразу (физический доверенный канал), но тот же
`vynkor://pair?d=...`, пришедший VIEW-intent'ом от любого другого приложения,
теперь показывает диалог «Connect to new host?» с `host_url` + `device_id`;
до явного «Connect» ничего не сохраняется и не коннектится. Это закрывает
связку «чужое приложение перепарило устройство → удалённая прослушка»
(вместе с R-01).

### Секреты: Keystore вместо plaintext (R-03)

- Профили хранятся AES-256-GCM ключом из AndroidKeyStore (`ProfileCrypto`),
  формат `base64(iv || ciphertext)` под ключом `profiles_enc`.
- Fail-closed: если шифрование недоступно, стор **не пишет** plaintext —
  изменение остаётся в памяти.
- Миграция при первом запуске: legacy-single-keys → plaintext-массив →
  encrypted. Старые данные читаются и перешифровываются автоматически.
- Битый store карантинится в `corrupt_<ts>_profiles*` (не стирается).
- Манифест: `allowBackup="false"` + `dataExtractionRules`/`fullBackupContent`
  — ни cloud-backup, ни device-transfer не уносят секреты.
- Комментарий «Never persisted by the app» в `rust/src/ffi.rs` исправлен —
  секрет хранится, но только зашифрованным и вне бэкапов.

### Жизненный цикл аудио (R-04)

Единый паттерн остановки для `MicCapture`/`SttRecorder`: `record.stop()` из
управляющего потока выводит блокирующий `read()` **до** join; release делает
поток-читатель (MicCapture) либо управляющий поток строго после успешного
join (SttRecorder; при таймауте — осознанная утечка вместо UB-release).
`stopAgent()` больше не джойнит потоки на main thread — очистка ушла на
background executor (ANR-риск снят). `SpeakerSinkImpl` получил idempotent
`release()`, неблокирующую запись и Builder API (deprecated
конструкторы/STREAM_MUSIC ушли).

## M2/M3. Надёжность сети и данных (P1, R-05…R-13)

### Протокол (Rust)

| Изменение | Что это значит снаружи |
|---|---|
| `check_payload_size` на всех outbound-путях | фрейм > лимита больше не рвёт соединение: push-пути дропают с warn+счётчиком, `request()` возвращает локальную ошибку |
| backoff сбрасывается после здоровой сессии (≥60 c) | рестарт хоста = reconnect через ~1 c, а не через вечные 30 c |
| register-ack timeout 15 c | хост, принявший handshake и молчащий, больше не клинит cap loop навечно |
| device→host Ping каждые 20 c + read deadline 40 c | half-open TCP (тихая потеря) детектится ≤40 c, реконнект автоматический |
| provider-вызовы и speaker-playback в `spawn_blocking`, воркеры 2→4 | медленные контакты/долгий TTS не стопорят остальные капы и read-loop |
| purge pending при обрыве/stop | заблокированные `request()` получают `Disconnected` немедленно |
| shutdown-флаг сбрасывается в `start()` | повторный start/stop на одном экземпляре работает (было: латентная мина) |

Попутно устранена гонка, которую вскрыл новый тест: stop() сразу после
start() мог зависнуть навечно — watch-канал теперь регистрируется синхронно
в `start()`, до спавна runtime-потока.

Новые тесты: restart-флаг, purge-pending-disconnects-waiters, backoff-политика,
oversized-drop-счётчик (22 всего).

### Контакты и чат

- contacts: `LIMIT 200` в SQL (полная адресная книга физически не может
  превысить payload-бюджет); параметр limit от хоста — отложено (нужен
  расширения foreign-trait).
- чат: на хост уходит окно последних 20 сообщений (`HISTORY_WINDOW`), а не
  вся история каждым запросом.

### Разрешения (R-10)

- Провайдеры (контакты/гео) проверяют грант **на каждый вызов** — выдача
  разрешения после старта сервиса начинает работать без рестарта; отзыв
  деградирует кап мягко (пусто/ошибка, без падений).
- Сервис стартует **после** резолва диалога разрешений (оба активити), а не
  fire-and-forget параллельно с ним.

### Локальная диктовка (R-11)

Эмуляция стриминга переработана: сессия = зафиксированный текстовый префикс +
bounded audio-хвост 15 c. Переполнение коммитится один раз (декод головы,
добавление к префиксу), так что CPU на тик и память сессии ограничены
константой независимо от длительности (было O(n²)/растущая память).
Рекордер копит в растущий `ShortArray` вместо `ArrayList<Short>`.
Жёсткий лимит сессии — 5 минут, авто-stop с тостом.

### ChatStore (R-12)

- один лок + in-memory кэш: JSON парсится один раз на профиль за процесс,
  конкурентные save не теряют обновления;
- запись асинхронная на IO-потоке (`chat-store-io`), сериализация под тем же
  локом — UI платит только за мутацию кэша;
- битый JSON карантинится в `corrupt_<ts>_<profileId>` — никаких молчаливых wipe;
- каждая запись сохраняет предыдущее сырое значение в `<profileId>_bak`.

### Мелочи

- `catch(Throwable)` → `catch(Exception)` в STT-путях: OOM/StackOverflow
  больше не глотаются.

## Фича: вход по отпечатку (2026-08-25, вне аудита)

`BiometricGate.kt` + проводка в `ChatActivity` (launcher):

- холодный старт требует отпечаток; при недоступности биометрии система
  предлагает PIN устройства (`BIOMETRIC_WEAK | DEVICE_CREDENTIAL`);
- на устройствах без зарегистрированных аутентификаторов гейт пропускает
  (иначе приложение было бы неработоспособно) — решение сознательное;
- пока экран заблокирован, контент скрыт от скриншотов и превью в recents
  (`FLAG_SECURE`), снимается после успеха;
- отказ/отмена/lockout закрывают приложение (`finishAffinity`), не оставляя
  его «полуоткрытым»; один промпт на процесс — последующие экраны
  (профили/настройки) не перепрашиваются;
- зависимость `androidx.biometric:biometric:1.1.0`.

Смоук на устройстве: промпт появляется, отпечаток открывает, cancel закрывает.

## Фичи: живая нотификация, auto-relock, battery events (2026-08-25)

Три связанные фичи поверх аудита (все смоукнуты на устройстве через adb):

**Статус соединения в foreground-нотификации.** `AgentObserver.on_state_changed`
обновляет строку нотификации: «Connecting…» → «Connected to `<host>`» →
«Reconnecting…». Хост берётся из имени профиля (fallback — host:port). Видно
из шторки без открытия приложения.

**Auto-relock.** Гейт биометрии больше не только на холодный старт: если
приложение провело в фоне ≥ 5 минут (`onStop` фиксирует момент, `onStart`
проверяет), разблокировка сбрасывается и промпт показывается снова.
Короткие уходы (< 5 мин) — без перепромпта.

**Battery events.** Новый push-метод `Agent.push_battery_status(level,
charging)` → `battery_status` event в kernel (роутинг через live-канал cap
`battery`). Kotlin `BatteryEventSource` слушает sticky
ACTION_BATTERY_CHANGED и дебаунсит: снапшот после регистрации + события при
Δуровня ≥ 5% или смене charging; остальное молча глотается. Разрешений не
требует (protected system broadcast, RECEIVER_NOT_EXPORTED).

Смоук-протокол (adb): `dumpsys battery set level 43/91/92` → события на 43 и
91, 92 задебаунсилось; офлайн-хост дал ожидаемый `dropping event` в logcat;
нотификация «Connecting…» подтверждена dumpsys notification; relock после
310 c фона создал новую AuthSession (`BiometricService` лог), возврат через
20 c — не создал.

## Фичи: настройки блокировки + статусы подключения (2026-08-25, вечер)

**Система блокировки (запрос владельца).** `SecurityStore` (prefs
`vynkor_security`: enabled / relock_minutes / salted-SHA-256 PIN-хеш) +
`LockActivity` — полноэкранный гейт: поле PIN (если задан) + кнопка
«Use fingerprint»; FLAG_SECURE пока заблокировано; назад = свернуть; 5
неверных PIN = закрыть приложение. `SecurityActivity` — секция
«Безопасность» в настройках: мастер-тумблер, задать/убрать PIN, слайдер
relock 1–60 мин (дефолт 5). Кнопка **Lock** (иконка-замок) в drawer рядом с
настройками. Гейт (`applyBiometricGate`) читает настройки: выключен → всегда
открыто; нет ни биометрии, ни PIN → проход (не бричить); фон ≥ N минут →
relock (трекинг фона через `ProcessLifecycleOwner` — app-level, чтобы ручной
Lock не взводил таймер). Смоук на устройстве: полный цикл PIN
(задать/lock/неверный/верный/remove) через uiautomator.

**Статусы подключения (запрос владельца).** `AgentObserver.on_status`
расширен (`ConnectionStatus::Connecting | ReachabilityFailed{reason}` —
UniFFI enum); Rust эмитит из `start()` и из каждой неудачной попытки
cap-loop'а с реальной причиной ОС/транспорта. Kotlin агрегирует в
`AgentHolder.hostStatus` (Idle/Connecting/Unreachable(reason)/Connected/
Reconnecting); Unreachable поверхится только пока ничего не live. Settings и
drawer показывают: 🟠 Connecting…/Reconnecting…, 🟢 Connected, 🔴 «Host
unreachable — No route to host» (реальная причина). Смоук: хост офлайн →
красный статус с причиной; восстановление хоста → Connecting → Connected.

**Честная кнопка подключения (найдено на смоуке).** Сервис автостартует при
открытии приложения (autoConnect), поэтому кнопка в Settings при
Connecting/Reconnecting/Unreachable фактически означала «остановить дозвон»,
но была подписана «Connect» — нажатие тихо отключало агента. Теперь лейбл по
статусу: Connected → Disconnect, Idle → Connect, иначе → **Stop**.

**Проекты (запрос владельца).** Изолированные группы чатов («папки»):
- `Project {id, name, created_at}` + `ProjectStore` (prefs `vynkor_projects`,
  per-profile, quarantine битого JSON — политика как у ChatStore);
- `Chat.projectId` ("" = «No project»/inbox), сериализация + авто-миграция
  старых чатов; `ChatStore.moveToProject` / `clearProject` (удаление проекта
  возвращает его чаты в inbox, чаты не удаляются);
- Drawer: секция **Projects** — чипы `All chats | <проекты>` (Filter-чипы,
  single selection) + «+»; выбор чипа фильтрует список чатов; **новый чат
  наследует выбранный проект**; long-press чипа → Rename/Delete;
- Long-press чата → «Move to project» (включая «No project»).
Смоук на устройстве: проект «Work» создан, чипы рендерятся (Work — выбран),
фильтрация и наследование подтверждены владельцем.

**Drawer (запрос владельца).** Иконка vynkor убрана — сверху сразу текст
«vynkor agent»; Lock теперь компактная иконка-замок слева от шестерёнки
(была широкая кнопка).

**Композер (запрос владельца).** Поле ввода больше не уезжает под
клавиатуру: `adjustResize` + IME-inset в общем паддинге (edge-to-edge).
Send и Mic — **один слот** справа от чипов (как в референсе): пусто/диктовка
→ 🎤 (при записи красная), есть текст → заполненный ➤; long-press в любом
режиме = host-стрим (R-01).
